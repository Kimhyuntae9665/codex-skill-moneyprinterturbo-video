# 레퍼런스를 Blender의 실제 연출로 바꾸기

2026-09-14. VibeEverything의 공개 자료를 선별해 얻은 제작 지침이다. ‘학습’은 관찰·원문 대조·설계 반영을 뜻한다. 다른 창작자의 모델 가중치·비공개 작업법을 확보했다는 뜻이 아니다. 현재의 쉬운 회사 이야기, Blender 미니어처, 이야기-화면 일치 기준을 유지한다.

## 1. 레퍼런스에는 역할을 지정한다

먼저 이번 장면의 결함을 한 문장으로 쓴다. 예: ‘돈을 건넨 상대가 다시 고객이 되는 반전이 화면에 안 보인다.’ 그 결함에 맞는 구도·움직임·연기 자료를 고른다. 멋진 샘플을 많이 모으는 것이 목표가 아니다.

AI 영상 갤러리에서 재질·카메라·편집·음향을 참고할 때는 [레퍼런스의 제작 적용 기준](../../mpt/references/reference-to-production.md)을 함께 읽는다. 역할별 자료 선택, 공개 생성 설정의 재현 한계, 관찰·제작자 설명·자체 시험 구분을 적용한다. 그 문서는 자료 분석용이며, 이 스킬의 Blender 중심 화면 구성이나 이야기 모드를 종목 분석 화면으로 바꾸지 않는다. 새 효과의 시험은 기존 고난도 구간 검수에 통합한다.

기존 `story-visual-map.md`의 훅·핵심 사건 행에 다음을 짧게 덧붙인다. 이미 승인한 자체 장면을 재사용하면 그 파일과 구간을 연결한다. 매 제작마다 외부 사이트 탐색이나 추가 문서 묶음을 요구하지 않는다.

| 기록 | 실제로 결정할 것 |
|---|---|
| 출처와 관찰 범위 | 게시물/원작 URL, 관찰일, 프레임·구간, 본문만/프레임 표본/연속 재생 여부 |
| 배울 한 가지 | 구도, 카메라, 조명, 인물 반응, 컷 연결 중 필요한 요소 |
| 보존/제외 | 예: 시선 연결만 학습; 원작 인물·대사·배경·브랜드는 재사용하지 않음 |
| 우리 장면의 구현 | 어떤 주체와 행동에 어떤 카메라/리그/광원 제어를 적용하는가 |
| 실제 확인 | 렌더 구간, 기대 변화, 결과/실패 이유 |

레퍼런스 검색에는 [Film Vibes](https://filmvibes.io/), [Frame Set](https://site.frameset.app/), 촬영 용어에는 [Cinematique](https://vvsvs.pro/cinematique), 움직임에는 [Camera Movement](https://www.aicameramovements.com/)를 선택적으로 사용한다. 검색 갤러리는 렌더러가 아니다. 작품 프레임 열람 권한과 최종 영상에 삽입할 권리는 다르다. 자료 자체를 쓸 때만 해당 권리를 확인한다. 검색/로그인이 막히면 승인된 자체 레퍼런스와 로컬 콘티로 계속한다.

## 2. 카메라 이름 대신 보이는 변화를 설계한다

아래는 자료에서 얻은 촬영 어휘를 우리 제작에 맞게 옮긴 독자적 예시다. 특정 창작자의 코드나 검증된 프리셋이 아니다.

| 시청자의 질문 | 선택 가능한 연출 | Blender에서 정할 값 | 탈락 조건 |
|---|---|---|---|
| 누가 누구와 거래하는가? | 관계를 읽는 master/two-shot | 회사별 actor ID, 상대 위치, 카메라 높이·거리·lens/FOV | 중요한 한쪽 회사나 전달 경로가 화면 밖 |
| 무엇이 바뀌었나? | 손/서류 insert 후 상대 반응 | 접촉 프레임, 손·소품 위치, 다음 컷의 동일 상태 | 서류가 컷 사이 다른 손으로 이동하거나 다시 생김 |
| 뒤에 무엇이 더 있나? | 전경을 지나 옆으로 이동하는 slider reveal | 실제 camera location 경로, 전경·주체·배경 간격, 대상 조준 | 단순 확대만 하고 가려진 정보가 드러나지 않음 |
| 같은 회사가 어떤 역할을 또 하나? | dolly-out으로 두 관계 공개 | 카메라 이동과 프레이밍, 결과 hold, 두 역할 라벨 영역 | 넓어졌지만 관계는 안 보이고 빈 세트만 증가 |
| 이 사건을 누가 알아차렸나? | 시선 → 대상 insert → 반응/OTS | eyeline, 카메라 축, 컷별 초점 대상 | 시선 방향과 다음 대상의 위치가 모순 |

`dolly/slider`는 카메라의 위치 변화, `zoom`은 렌즈/FOV 변화다. 둘을 같은 ‘확대 효과’로 처리하지 않는다. 정적 시점이 행동을 가장 잘 보여주면 그대로 사용한다. 모든 컷의 궤도 회전·핸드헬드·얕은 심도를 의무화하지 않는다.

주요 컷에는 카메라 시작/끝 위치, 보는 대상, lens 또는 FOV, 화면상 이동 방향, 초점 대상, 필요한 경우 경로 키프레임을 적는다. 인물의 이동축과 시선이 바뀌면 연결 구도나 재설정 컷으로 관계를 다시 보여준다. 이유 없는 좌우 반전은 고친다.

‘ARRI, 8K, cinematic’이라는 프롬프트만으로 실제 렌더가 좋아졌다고 하지 않는다. 조명은 방향·광원 크기/부드러움·그림자 형태로, 색은 주체/소품/공간의 반복 팔레트로 번역한다. 기존 polish 시험에서 구도와 재질을 분리하기 어려울 때만 같은 카메라의 단순 재질/최종 재질을 비교한다. 매 컷 여러 버전 렌더를 강제하지 않는다.

## 3. 인물은 감정 형용사보다 반응 동작을 갖는다

[감정 연기 라이브러리](https://seedance-emotion-direction.vercel.app/)는 추상 감정을 보이는 연기로 쪼개는 참고자료다. 원래 AI 영상용 프롬프트이므로 Blender 리그에 자동 적용된다고 가정하지 않는다.

우리 장면에서는 `사건/자극 → 시선 → 자세·손 반응 → 잔동작·결과`로 만든다. 예를 들어 예상 밖 청구서를 받은 직원은 종이를 보고, 고개를 약간 물리고, 내밀던 손을 멈춘다. 외치는 표정이나 큰 점프가 없어도 반전을 전달할 수 있다. 이 예시는 설명용 배우의 반응이며 실제 경영진 심리를 입증하지 않는다.

- 시선/고개/어깨/손 중 화면에서 읽히는 제어를 선택한다. 얼굴 리그가 없거나 얼굴이 작으면 몸 자세와 소품으로 표현한다.
- 약·중·강은 해당 장면의 움직임 크기와 속도를 비교하는 선택지다. 모든 감정에 세 버전 제작을 요구하지 않는다.
- 자극보다 먼저 놀라거나, 양손이 소품을 관통하거나, 다른 컷에서 준비 자세로 리셋되면 실패다.
- 새 타임라인을 만들지 않고 기존 `action-cues.json`의 사건 시각에 reaction 시작·contact·settle을 연결한다. fps와 편집 음성 기준으로 실제 프레임을 정한다.
- 얼굴·몸·의상은 동일 리그/어셋 식별자로 유지한다. 필요한 기본 자세는 Blender blockout으로 직접 만들 수 있다. [3D 포즈 참고 게시물](https://x.com/VibeEverything/status/2077030433972490426)과 [작성자가 밝힌 도구](https://x.com/VibeEverything/status/2077030437080506640)는 PoseMy.Art/POSEMANIACS를 소개하지만 새 도구 설치는 필수가 아니다.

## 4. 얼굴·의상·구도를 한 참조로 뭉뚱그리지 않는다

반복 인물이 있으면 world sheet에 `identity`, `wardrobe`, `pose/blocking`, `lighting/composition`의 참조 역할을 나눈다. 한 이미지의 배경이나 자세가 다른 컷까지 의도치 않게 복제되지 않게 보존/제외 요소를 쓴다. Blender에서는 동일 캐릭터와 재질을 재사용하는 것이 기본이다.

[XAZINGA 시트 소개](https://x.com/VibeEverything/status/2099076532719464724)의 전신 얼굴 제거는 생성 모델 입력을 분리하려는 요령이다. **우리 Blender 캐릭터의 얼굴을 없애라는 규칙이 아니다.** 생성형 보조 컷이 필요할 때만 얼굴 클로즈업·의상 전신 참조 분리를 비교 시험한다. 일관성 개선은 해당 모델의 실제 결과를 보고 판정한다.

[Soul2 스킬](https://github.com/promptwhat/promptwhat-soul2-skill)에서 참고할 것은 구도→정체성→의상/소품→배경→조명/팔레트를 분리하는 설계다. Higgsfield용 프롬프트 스킬을 Blender 의존성으로 설치하지 않는다. 그 저장소의 기본 라이선스와 원저작자 소유 golden prompts의 예외도 구별한다. 회사 소개에 필요한 실제 로고까지 일괄 금지하는 제약은 가져오지 않는다.

### 반복 인물의 시트와 실제 컷을 연결한다

2026-09-22에 확인한 [캐릭터 시트 게시물](https://x.com/VibeEverything/status/2091399782678020100)의 첨부 두 장은 여러 방향의 전신·머리 모습과 얼굴·손·소품 디테일을 나눠 보여준다. 이 구성에서 필요한 부분만 자체 캐릭터에 적용한다. 원작 인물이나 그림을 우리 자산으로 재사용하는 지침이 아니다.

- 반복 인물이 이야기의 식별에 필요할 때만 같은 Blender 어셋에서 정면·측면·후면 중 실제 컷에 필요한 뷰를 만든다. 얼굴 클로즈업이 있으면 별도 얼굴 뷰, 손으로 전달하는 사건이 있으면 손·소품 접점 뷰를 보탠다. 모든 영상에 사람이나 전체 시트 제작을 강제하지 않는다.
- 각 뷰는 동일 `character_id`, 어셋 버전, 의상·재질, 머리 형태, 체형, 주요 소품을 참조한다. 소품의 시작 손·위치와 이후 이동은 장면 사건으로 기록한다. 의도된 상태 변화까지 고정해 행동을 막지 않는다.
- 시트는 검토용 묶음이고 실제 참조 원본은 개별 뷰로 보존한다. 작은 얼굴이 들어간 전신 콜라주를 확대해 얼굴 디테일 원본으로 쓰지 않는다. 생성형 보조 컷에서는 모델이 지원하는 참조 방식에 맞춰 필요한 뷰만 선택하고 각 이미지의 역할을 지정한다. 콜라주 패널·테두리·복수 인물이 결과에 따라 나오는지 확인한다.

### 인물의 동일성과 선명도를 별도로 검수한다

기존 고난도 구간 시험에서 아래 항목을 나눠 기록한다. 하나의 ‘얼굴 품질 점수’로 합쳐 다른 실패를 가리지 않는다.

| 확인할 문제 | 관찰할 차이 | Blender에서 먼저 수정할 것 |
|---|---|---|
| 다른 인물처럼 보임 | 컷 사이 얼굴 비율·머리·체형·의상·소품의 불일치 | 동일 어셋/리그/재질 버전과 상태 전달 확인 |
| 같은 인물이지만 흐림 | 원본 렌더와 최종 인코딩에서 눈·입·손의 디테일 차이 | 화면상 크기·초점·모션블러·텍스처와 출력 해상도를 원인별 확인; 단순 샤프닝으로 대체하지 않음 |
| 정지 프레임은 좋지만 움직임이 깨짐 | 고개 회전·가림 뒤 재등장 때 얼굴 변화, 소품 점프, 손 관통 | 리그·제약·접촉·컷 연결 수정 후 해당 구간 재생 |

필요한 경우 같은 인물의 근접·중간·전신 컷을 비교하되 본편에 없는 구도를 시험 목적으로 모두 만들지 않는다. 얼굴만 선명하게 만들기 위해 회사 간 관계나 손의 접점을 프레임 밖으로 밀어내지 않는다. 최종 인코딩과 휴대폰 표시 크기에서도 의도한 표정·행동이 읽히는지 확인한다.

### 채택하지 않은 주장과 관찰 범위

위 게시물 본문은 얼굴 참조에 의도적으로 손상을 주면 출력 선명도가 개선된다는 설명을 전한다. 그러나 [반론 댓글](https://x.com/HaowenAI/status/2091429414760292739)은 다른 목적을 주장하며, [작성자 답글](https://x.com/VibeEverything/status/2091431567164145984)에도 검열 회피 언급이 있다. 댓글 어느 쪽도 통제된 화질 비교 실험은 아니다. **얼굴 훼손·격자 추가를 검증된 품질 개선법이나 기본 전처리로 등록하지 않는다.** 이용 제한 우회와 무료 크레딧 어뷰징도 기존 제외 기준을 유지한다.

이번 확인 범위는 본문·관련 댓글, 캐릭터 시트 두 장, 10초 첨부 영상의 표본 프레임이다. 동일 조건의 전후 비교·연속 재생 검수·청취는 하지 않았다. Toonkit 출처 링크의 존재와 실제 원 제작 설정 확보를 구분한다. 위 어셋·검수 절차는 우리 Blender 제작에 맞춘 설계이며 이번 문서 수정만으로 품질 향상이 검증된 것은 아니다.

## 5. 세로 화면과 컷 연결을 함께 검수한다

[가로→세로 재구성 원문](https://x.com/VibeEverything/status/2094379012303077431)의 핵심은 행동·관계를 보존하는 것이다. Blender 제작은 처음부터 9:16으로 설계한다. 가로 자료를 참조할 때는 다음 순서로 해결한다.

1. 주체 둘, 접점, 경로, 결과 중 반드시 보여야 할 영역을 정한다.
2. 카메라 거리·높이·렌즈·coverage/추가 컷으로 먼저 해결한다. 위아래를 늘리거나 가운데만 크롭해 한쪽 당사자를 지우지 않는다.
3. 그래도 필요하면 상대 역할·전달 방향을 보존하며 blocking을 조정하고 연결 컷도 함께 검수한다. 매 프레임 소품을 임의로 재배치하지 않는다.
4. 첫/끝 프레임과 인접 컷 쌍에서 인물 수, 좌우·시선, 손/소품 상태, 조명/노출, 자막 겹침을 확인한다. 기존 whole-frame/continuous-motion QA에 합쳐 기록한다.

외부 프롬프트의 global/shot/negative 규칙끼리도 대조한다. 공개된 [20초 드라마 설계](https://x.com/VibeEverything/status/2095076490270642552)는 상세한 등장 시점과 좌우 고정을 참고할 만하지만 문 열기 장면과 전역 금지에 상충하는 표현도 있다. 13컷이라는 수나 ‘모든 컷 핸드헬드’를 회사 이야기의 고정 템플릿으로 복사하지 않는다.

## 6. 도구 채택은 실제 결함과 실행 환경으로 결정한다

외부 생성 도구의 역할별 시험, 한국어 TTS 비교, 장면용 BGM 설계는 [생성 도구 선택 기준](../../mpt/references/generative-component-selection.md)을 따른다. 제작 전체를 다른 서비스로 옮기지 않고 부족한 요소만 시험한다. 무료 플랜 소개를 수익화용 최종 출력 사용 허가로 해석하지 않는다.

| 후보 | 현재 결정 | 이유/다시 검토할 조건 |
|---|---|---|
| 촬영·연기·프레임 라이브러리 | 선택적 참고 | 원리를 자체 Blender 장면으로 구현; 사이트 의존 납품 금지 |
| [Movin](https://movin.design/)·[easing](https://movin.design/easings/) | 보조 모션 참고 | 로고/자막/짧은 전환용; 웹 좌표와 CSS를 3D 물체 동작에 그대로 적용하지 않음 |
| [TapirConvert](https://tapirconvert.com/video-upscaler) | 필요할 때만 짧은 비교 시험 | 공식 설명은 로컬 브라우저 2×/4×. 공급자 주장과 우리 성능 검증을 구분. 자체 Blender는 원본 재렌더를 먼저 검토; 업스케일은 구조/연기 수정 수단이 아님 |
| [Palmier Pro](https://github.com/palmier-io/palmier-pro) | 현재 기본 파이프라인에서 제외 | 2026-09-14 공식 README상 Apple Silicon macOS용. 현재 Windows/원격 Linux에 맞지 않음. 과거 GPL 소스와 이후 비공개 바이너리도 구별 |
| 신규 유료 생성 서비스·무료 크레딧 행사 | 도입 근거 부족 | 기존 제작의 어떤 실패를 고치는지, 플랫폼/비용/권한/짧은 비교 결과가 있어야 채택 |
| [1920×1088 지시 요령](https://x.com/VibeEverything/status/2091762776402477390) | 모델 한정 미검증 가설 | 게시물은 프레임 변형을 해결하려 한 시도 설명. Blender 납품 규격을 바꾸거나 모든 모델의 성공 법칙으로 쓰지 않음 |

검열 우회·무료 크레딧 어뷰징·워터마크 제거는 이번 제작 품질 개선에 채택하지 않는다. 작성자가 공유한 방법이라는 사실과 우리가 실행할 이유·권한은 별개다.

## 7. 적용 예시 — 미제작 12초 콘티

가상의 ‘투자자가 다시 공급자가 되는 이야기’ 연출 예시다. 실제 회사·금액·계약을 주장하지 않는다. 기존 본편에서 해당 사건이 필요한 경우에만 사용한다.

| 구간 | 화면 사건 | 연출과 확인 |
|---|---|---|
| 0–3초 | 왼쪽 투자자와 오른쪽 창업자가 책상 위 투자 서류를 전달 | 투샷에서 두 역할 소개. 손-서류 접점과 받는 사람의 시선이 보임 |
| 3–6초 | 같은 창업자가 별도의 서비스 신청서를 작성 | insert로 문서 종류 변화. 투자 서류가 변신하거나 같은 돈이 환수되는 그림을 피함 |
| 6–9초 | 옆 창구에서 공급자 역할이 드러남 | 전경 간판을 지나는 짧은 slider; 창업자가 먼저 쳐다보고 잠깐 멈춤 |
| 9–12초 | 넓어진 시야에서 투자자와 공급자가 같은 기업 영역에 속함을 공개 | dolly-out 뒤 결과 hold. 두 관계를 다른 선·라벨로 구별하며 세로 프레임에 남김 |

기존 10–15초 선행 검수에 이런 구간을 포함하면 된다. 별도 시험 영상을 매번 추가로 만들라는 뜻이 아니다. 위 콘티의 Blender 렌더·청취·시청자 반응은 이번 문서 작성으로 검증되지 않았다.
