# 조건부 실사풍 제작 참고 — 현재 기본 스타일이 아님

**적용 범위 갱신:** 후속 실사풍 Amazon은 내용-화면 불일치로 다시 반려됐다. 현재 기본은 `story-aligned-miniatures.md`의 정교한 미니어처다. 아래 실사 기준은 향후 사용자가 실사풍을 명시했을 때만 적용한다. 미니어처 전체를 금지하거나 외형을 이야기보다 우선하는 근거로 사용하지 않는다.

이전 2026-09-06 실사풍 요청 기록: 시간과 허용된 원격 GPU를 더 사용하더라도 실사처럼 완성도를 높인다. 이전 Amazon 미니어처 제작본은 기술적으로 정상 출력됐지만 요청한 시각적 품질에는 실패했다. 쉬운 회사 이야기와 Blender·원격 GPU 기본값은 유지하며, 아래 기준은 그 결과물의 품질을 정의한다.

## 실패 원인

- 인물을 구·원통으로 즉석 조립하고 큰 머리와 무표정 얼굴, 단단한 머리 덩어리를 사용해 목각 장난감처럼 보였다.
- 실제 실내에서 촬영하는 구도가 아니라 벽 두 장만 세운 지붕 없는 세트를 바깥에서 내려다봤다. 검은 빈 공간과 바닥판의 끝이 반복 노출됐다.
- 가구·모니터·키보드의 비율과 세부가 실제 제품과 달랐고, 재질의 작은 변화만 추가했을 뿐 어셋 자체의 완성도가 부족했다.
- '3D 장면 수'와 '떠 있는 물체 없음'을 확인하고 실사감·공간 완성도를 별도 탈락 조건으로 검사하지 않았다.

샘플 수, 해상도, GPU 시간은 위 문제의 해결책이 아니다. 설계·어셋·카메라를 고친 뒤 빛과 렌더를 개선한다.

## 제작 순서

1. **룩 목표를 먼저 고정한다.** 실제 참고 화면 2~3개에서 인물 비율, 카메라 높이, 공간의 연속성, 재질과 조명의 구체적 특징을 기록한다. 제작자가 도구를 공개하지 않았다면 영상 외관만으로 모델/LoRA/렌더러를 단정하지 않는다. 원본 대사·프레임을 그대로 재사용하지 않고 시각 원리를 새 이야기로 옮긴다.
2. **완성된 세계를 설계한다.** 실내는 바닥·벽·천장·창호·설비가 일관된 스케일로 이어지고 카메라는 그 안에 위치한다. 외관은 지붕/상층부/파사드·문·주변 거리의 연속성이 있다. 명시적 설명용 단면을 제외하면 지붕 없는 인형집·떠 있는 바닥판·회색 무대 빈 공간을 금지한다. 프레임 밖 천장도 반사·그림자에 필요한 경우 모델링한다.
3. **어셋의 출처와 품질을 확인한다.** 검증 가능한 CC0/PBR 자료·현실적인 치수의 모델을 우선하고, 직접 제작할 때도 제품 사진의 비례·엣지·구조를 참고한다. 재질은 스케일이 맞는 거칠기/노멀·금속/유리·미세 변화를 사용한다. 거친 노이즈만 얹어 플라스틱 장난감을 실사라고 하지 않는다.
4. **사람을 가장 엄격하게 검수한다.** 사실적인 피부·머리카락·의복·관절·접촉을 구현할 수 없다면 손/어깨너머/자연스러운 넓은 실사풍 인물 장면을 사용한다. 목각/마네킹 어셋으로 사람 자리를 채우지 않는다. 적절한 라이선스의 촬영물 또는 검수한 생성 영상을 Blender와 혼합할 수 있다. 실제 회사 직원/시설이라고 오인시키지 않는다. 반복 인물의 복장·외형·역할을 유지한다.
5. **가장 위험한 장면부터 증명한다.** 인물 포함 장면, 완성된 건축 공간, 소품 근접 장면을 대표로 뽑아 native 크기로 검사한다. 가장 어려운 2~4초 동작을 먼저 렌더·디코딩하고 시간에 따른 손·얼굴·문·물체의 변형을 검사한다. 실사감이 실패하면 전체 렌더를 시작하지 않는다. 사용자 추가 승인을 자동 요구하는 게이트가 아니라 제작자가 직접 고칠 기준이다.
6. **계산을 품질에 연결한다.** 고품질 어셋·정확한 접촉·조명/반사/카메라·동작 설계→충분한 샘플과 디노이즈 순서로 투자한다. 원격 GPU 사용량·VRAM·RAM·디스크를 확인한다. 기존 설치 모델을 우선 쓰되, 한 장면에서 어떤 결함을 해결할지 명확하면 새 도구를 조사한다. 더 큰 모델 설치 자체를 진행 성과로 취급하지 않는다.
7. **합성도 영화의 일부다.** 로고·출처·핵심 수치를 후합성하고 사람 얼굴과 행동을 가리지 않는다. 실제 시설처럼 보이는 생성 장면은 설명용 재현임을 명시한다. 입체 움직임이 필요한 부분을 정지 이미지 확대만으로 대체하고 '동영상 생성'이라고 보고하지 않는다. 클립 중 실제 움직임·카메라만 움직임·정지 삽입을 구분해 기록한다.

## 원격 8GB GPU에서 확인한 실행 주의점

- 이번 SVD 시험에서 576×1024·25프레임은 메모리 부족으로 실패했다. 14프레임·CPU offload·UNet chunking·decode chunk 2 조합은 약 160초에 출력됐으며 peak allocation은 약 5.55GiB였다. 이는 해당 설치/장면의 실측이지 모든 모델의 보장값이 아니다.
- 생성 latent를 먼저 저장한 뒤 디코딩한다. 디코딩만 실패했으면 저장 latent를 재사용해 전체 추론을 반복하지 않는다. GPU 생성과 Cycles는 같은 8GB 장치에서 겹쳐 실행하지 않는다.
- 7fps 원본을 30fps로 보간하거나 확대했다고 native 30fps/1080p 생성이라고 보고하지 않는다. 원본 해상도·프레임 수·리타이밍·보간 방법을 장면별로 남긴다. 보간 후 손/보행/모서리의 잔상도 다시 확인한다.
- 실사풍 사진 한 장과 미세한 카메라 이동만으로 충분한 동작을 구현했다고 하지 않는다. 실제 보행/손동작, 카메라 이동, 정지 삽입을 구분한다. 핵심 인과 동작은 제어 가능한 Blender 애니메이션이나 검증된 동작 클립으로 구현한다.
- 사진풍 기준 이미지를 만들기 전에도 무엇을 보여줄지 먼저 정한다. 실제 직원이나 실제 계약서처럼 보이는 장면은 설명용 재현이며, 로고·금액·날짜는 후합성한다.
- 생성 클립과 Blender 클립을 합칠 때 해상도·픽셀 비율·프레임률/시간 기준을 통일한다. 정지 로고 입력은 전체 합성 구간에 유지하고, 포맷 전환 뒤 로고/그라데이션이 사라지지 않았는지 실제 후반 프레임으로 검사한다.
- 자막 시작/종료와 영상 컷을 동일한 최종 프레임 인덱스에 맞춘다. 원래 오디오 초값을 자막에 그대로 쓰고 영상만 프레임 단위로 반올림하면 한 프레임의 잘못된 자막이 남을 수 있다. ASS처럼 시간 정밀도가 다른 형식은 실제 컷 프레임에서 올바른 문장이 표시되는지 검사한다.

## 최종 판정 기록

QA에 `realism`, `environment_completeness`, `human_quality`, `temporal_integrity`, `reference_similarity`를 기술 검증과 별도로 쓴다. 인물이 없으면 human_quality는 not_applicable이다. 실제 검수하지 않은 항목은 not_performed이며, 주관적 점수를 측정된 품질로 표현하지 않는다. 원래의 기술 pass는 보존하되 사용자 반려본의 `realism`은 rejected_by_user로 갱신한다.

다음 중 하나라도 주 장면에 남으면 실사풍 완료로 납품하지 않는다: 장난감 인물, 지붕/천장 없는 비의도적 세트, 제품 비율 오류, 눈에 띄는 손/얼굴 변형, 이유 없는 물체 떠있음, 동일한 빈 세트 반복. 남은 결함은 구체적으로 밝히고 재제작한다. 기존 원격 GPU 권한을 활용하되 유료 서비스 구독·결제까지 포괄 승인으로 확대하지 않는다.
