# 생성 영상 실행 시험: 수신과 채택은 다르다

2026-09-05, [Lightricks의 공개 LTX Video 데모](https://huggingface.co/spaces/Lightricks/ltx-video-distilled)에서 실제로 세 번 생성했다. 당시 앱 표기는 **LTX Video 0.9.8 13B Distilled**, 공개 저장소 커밋은 `8a42e93469c66b62d794b83a4233f5fc8439e2b5`였다. 현행 LTX-2/2.3이나 Flow의 평가로 일반화하지 않는다.

익명 공개 API로 실행했으며 사용자 계정 토큰·유료 서버·새 구독을 사용하지 않았다. 당시 공개 앱이 열려 있었다는 기록이지 영구 무료 접근이나 일정한 처리시간의 보장은 아니다. 요청 전 앱의 실제 API 설명을 읽고 입력 순서를 확인했다.

## 조건과 결과

각 요청은 2초, 384×704, seed 42였다. 돌아온 MP4는 각각 약 1.9초·30fps·57프레임이다. 이 길이 차이 때문에 생성 요청값을 완성 편집 길이로 그대로 믿지 않는 규칙을 추가했다. 아래 판단은 약 0.2초 간격 샘플 프레임으로 확인한 범위다.

| 시험 | 입력 / 원하는 동작 | 실제 관찰 | 판정 |
|---|---|---|---|
| 닫힌 냉각판 공개 | 직접 렌더한 원본 이미지 → 뚜껑을 들어 뒤로 이동 | 경첩 달린 상자처럼 열림. 호스가 뚜껑을 따라 이동하고 기대한 내부 통로가 없음 | 파일 생성 성공, 구조·동작 채택 실패 |
| 이미 열린 통로 | 연결을 수정한 원본 3D 이미지 → 흐름 표시 이동 | 외형을 대체로 유지하지만 점의 뚜렷한 통로 이동이 샘플에서 확인되지 않음 | 파일 생성 성공, 동작 입증 부족 |
| 작업자 맥락 | 텍스트 → 장갑 낀 손으로 밸브를 1/4회전 | 손과 랙 배경은 생성됐지만 밸브 자체와 회전 동작을 확인할 수 없음 | 파일 생성 성공, 핵심 사물·행동 채택 실패 |

이 세 결과를 최종 설명 영상의 승인 장면으로 사용하지 않았다. 입력 이미지는 모두 이번에 만든 원본 장면이고, 세 번째 인물은 텍스트로 생성한 가상의 인물이다. 별도로 만든 캐릭터 시트와 동일 인물이라는 검증은 없다.

추가로 원격 SDXL에서 생성한 서버실 이미지를 넣어 4초 전진 카메라 장면을 요청했다. 공개 API가 오류 이벤트와 `null`을 반환해 영상 파일을 받지 못했다. 구체적인 실패 원인은 응답에 없었으므로 GPU 부족·일일 할당량 등으로 단정하지 않았다. 따라서 **총 네 번 요청, 세 개 MP4 수신**, 네 번째는 서비스 실행 실패로 구분한다. 실패한 영상의 프레임을 보았다고 기록하지 않는다.

## 실패를 다음 제작 지시로 바꾸기

- **보이지 않는 내부를 상상시키면** 필요한 연결이 빠질 수 있다. 승인한 열린 구조를 먼저 제공하거나 검증한 3D를 쓴다.
- **뚜껑만 움직인다는 문장**이 물리적 연결을 보장하지 않는다. 호스가 붙는 대상과 뚜껑의 이동 방식도 확인한다.
- **외형을 보존하는 것**과 **설명에 필요한 행동을 하는 것**은 별개다. 정지에 가까운 생성물에 속도만 붙여 동작 성공으로 보고하지 않는다.
- **사람을 먼저 길게 묘사하면** 밸브처럼 중요한 물체가 빠질 수 있다. 주 사물의 구성부터 검증한다. 이 수정이 실제로 성공했다고 미리 말하지 않는다.
- 한 모델의 실패를 모든 생성 모델의 실패로 일반화하지 않는다. 다만 같은 실패를 무한 재시도하지 않고 장면의 역할을 바꾼다.

## 접근 가능한 경로를 구분하기

Flow는 이번에 Google 계정 선택 단계에 머물러 생성하지 못했다. 공개 LTX 데모는 실제 MP4를 받았다. Blender/OptiX는 사용자 제공 원격 GPU에서 실제 렌더했다. 이 세 경로의 상태를 하나의 ‘AI 영상 생성 완료’로 합치지 않는다.

생성 결과물의 지각적 품질은 모델·입력·동작·해상도에 따라 달라진다. 최종 원작 수준의 검증은 접근 가능한 고품질 모델에서 대표 장면을 생성하고, 같은 평가 항목으로 비교해야 한다.
