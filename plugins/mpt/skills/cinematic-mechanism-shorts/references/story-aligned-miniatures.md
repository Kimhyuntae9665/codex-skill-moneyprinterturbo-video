# 이야기와 화면이 일치하는 정교한 미니어처

2026-09-06 최신 사용자 수정. 사용자가 직접 고른 기준작은 `NVIDIA_경쟁칩을환영하는이유_v2.mp4`다. 과거의 미니어처 전면 금지·실사 우선 규칙을 대체한다. 유지할 것은 설명 대상의 연속성과 관계가 보이는 행동이며, 고도화할 것은 어셋·인물·무대·조명·동작의 완성도다. 칩이나 회색 배경 자체를 다른 회사에 복사하지 않는다.

## 1. 아마존 실패의 원인과 판단 순서

실사풍 사무실, 서류를 만지는 손, 서버실 문, 달력, 로비, 휴대전화는 각각 관련 명사를 연상시킬 수 있다. 그러나 그것만으로 Amazon의 투자, Anthropic의 고객 역할, AWS의 서비스 제공 및 지출 약속은 보이지 않는다. 로고 워터마크와 나레이션이 이 빈칸을 대신 채운 것이 실패다. 문이 열리고 사람이 걷는다고 이야기의 인과 동작을 구현한 것은 아니다.

판단 순서는 **사실에 맞는 관계 → 그 관계가 보이는 사건 → 알아볼 수 있는 대상과 공간 → 일관된 스타일과 완성도 → 기술 납품**이다. 앞 항목의 실패를 실사감·해상도·샘플 수·장면 수·GPU 시간으로 상쇄하지 않는다.

## 2. 대본을 장면으로 번역하는 계약

핵심 설명 구간마다 `story-visual-map.md`에 다음을 기록한다. 같은 사건이 여러 컷에 걸치면 한 묶음으로 평가한다.

| 필드 | 작성할 내용 |
|---|---|
| 대본/주장 | 이번 구간에서 시청자가 알아야 하는 한 가지 |
| 등장 주체와 역할 | 누가 투자자/고객/공급자인가; 회사명과 관계를 구분 |
| 화면에 있는 대상 | 이름·형태·색·위치로 구별되는 실제 장면 요소 |
| 시작 → 행동 → 결과 | 어떤 관계가 어떤 동작을 통해 달라지는가 |
| 관찰 가능한 증거 | 검수할 프레임/구간과 화면에서 확인할 변화 |
| 연속성 | 이전 컷의 무엇이 이어져 같은 대상임을 알 수 있는가 |
| 비유와 한계 | 모델이 설명하는 관계 및 실제 사실로 오해할 부분 |
| 탈락 조건 | 예: AWS 식별은 되지만 서비스가 누구에게 가는지 안 보임 |

핵심 주장에는 이름/역할 + 연결된 행동 + 결과가 필요하다. 배경 소개 컷은 허용하지만 새로운 핵심 주장을 분위기 컷에 맡기지 않는다. 다른 회사 이름으로 바꿔도 아무 수정 없이 쓸 수 있는 장면이라면 관계 설명이 빠졌는지 먼저 점검한다. 이 교체 검사는 경고이며 모든 범용 어셋 사용을 금지하는 규칙은 아니다.

내레이션과 긴 설명 자막을 끈 상태에서도 짧은 회사명·역할 표시는 남겨 두고, 누가 무엇을 보내고 받는지 확인한다. 정확한 숫자·계약 조건까지 무음 화면으로 모두 전달하라는 요구는 아니다. 그다음 음성과 함께 재생해 같은 관계와 시점을 말하는지 대조한다.

## 3. NVIDIA 기준작에서 유지하고 높일 것

첨부본 직접 검사: 48.041667초, 1080×1920, 24fps. 0~44초 4초 간격 이미지와 병목 구간 10~17.5초의 0.5초 간격 이미지를 표본 검토했다. 첨부본 SHA-256은 `260225F645EC0E0DA012E6DDB9A09EB0662B8ACC2F8653552517BC3B2FB2E812`이며 기존 NVIDIA v2 출력본과 일치했다. 이 기록은 전 구간 청취 판정이 아니다.

- **유지:** 알아볼 수 있는 ASIC → 내부 공개 → 전송 대기 → GPU/NVLink 연결 → Marvell 역할 → CPU/NIC/스위치 → 랙 규모로 확장. 설명의 대상이 연결망과 구성품으로 화면에 남는다. 사용자 선택은 현재의 비교 기준이지 모든 결함이 해결됐다는 뜻이 아니다.
- **고도화 1 — 공간:** 회색 빈 무대의 반복을 줄이고 설명이 필요한 작업대·연결 시험대·랙 공간을 모듈화한다. 처음 보는 위치로 점프할 때는 동일 부품이나 연결선을 따라 이동한다.
- **고도화 2 — 인과:** 병목에서는 입구 적체와 출구 대기를 함께 보여주고, 해결 뒤 같은 경로에서 변화가 보이게 한다. 블록을 단순히 빛나게 하는 것으로 처리량 증가를 단정하지 않는다. 상징적 데이터라는 표시와 실제 제품 동작의 범위를 구분한다.
- **고도화 3 — 상세:** 칩의 모서리·핀·기판, 랙의 패널·케이블·바닥 접촉을 화면에서 보이는 크기에 맞춰 개선한다. 실제 제품의 내부 구조를 모르면 개념 모형으로 표현한다.
- **고도화 4 — 행동:** 모듈 안착, 케이블 연결, 경로 활성화 등 서사를 설명하는 짧은 동작을 추가한다. 임의의 조립 순서를 실제 설치 방식으로 주장하지 않는다.
- **고도화 5 — 구도:** 영웅 오브젝트, 변화 지점, 결과 순으로 시선을 유도한다. 얕은 심도·반사·불꽃·인물이 중요한 연결선과 라벨을 가리면 줄인다. 컷마다 새 세트를 강제하지 않는다.

## 4. 미니어처 인물과 공간의 완성도

인물은 이야기 속 역할을 수행할 때 등장한다. 계약 당사자, 서비스 이용자, 연결 작업자처럼 작업을 명확히 하고 장식용 군중은 피한다. 실사 인물을 다른 스타일로 끼워 넣어 분위기를 바꾸지 않는다.

- 하나의 캐릭터 시트: 몸/머리 비례, 얼굴 단순화 수준, 머리카락, 의상, 신발, 역할색, 반복 소품을 고정한다. 미니어처 표현은 허용하되 구·원통을 급조한 목각 형태로 납품하지 않는다.
- 옷의 형태와 관절 굽힘이 구별되고 손이 서류·손잡이·도구와 실제로 닿아야 한다. 손을 크게 보여줄 필요가 없으면 디테일을 억지로 확대하지 않는다.
- 걷기에는 지지발과 무게 이동, 서명에는 손/펜/종이 접촉, 착석에는 의자/발 접촉이 필요하다. 움직이는 물체를 끝까지 보게 한 뒤 컷한다. 발 미끄러짐·관통·동작 중 비례 변화는 탈락이다.
- 대표 인물의 정지 자세뿐 아니라 필요한 실제 행동의 2~4초 시험을 검수한다. 사용할 리그/어셋은 라이선스와 수정 가능성을 확인하고, 제대로 되는 행동을 재사용한다. 자동으로 특정 유료 도구를 요구하지 않는다.
- **의도된 단면과 미완성 건축을 구분:** 먼저 완성된 외형을 보여준 뒤 지붕/벽을 정돈된 방향으로 제거하거나 일관된 단면 경계로 연출할 수 있다. 이유 없는 벽 두 장·허공의 바닥·잘린 가구·지지 없는 조명은 허용하지 않는다.
- 미니어처에도 창호, 가구 비례, 재질 차이, 접촉 그림자와 소품 배치가 필요하다. 배경을 채우는 양보다 이야기와 관련된 세부를 우선한다. 모든 공간을 실내 풀세트로 만들 필요는 없다.

## 5. Amazon을 이렇게 다시 설계할 수 있다 — 미제작 예시

이 예시는 관계 번역 방법이며 고정 템플릿이나 새 영상 완성 보고가 아니다. 금액·시점은 다음 제작 때 해당 발표와 다시 대조한다.

| 이야기 | 화면 사건 | 피할 오류 |
|---|---|---|
| 투자자이면서 공급자 | 한 무대에 Amazon 투자 역할, Anthropic, Amazon 영역 안 AWS 서비스 역할을 구별. 두 방향 관계를 예고 | 간판만 붙은 일반 사무실 |
| Amazon이 Anthropic에 투자 | Amazon 쪽에서 Anthropic 쪽으로 `투자` 카드 이동, Anthropic 역할 인물이 인수 | 이 카드가 AWS로 그대로 돌아가는 것처럼 추적 |
| AI 운영에는 컴퓨팅 필요 | 같은 Anthropic 인물이 작업을 요청하고 작업 대기 상태가 보임 | 모르는 사람이 모니터를 보는 클립 |
| AWS가 컴퓨팅 제공 | AWS 표식의 서비스 설비에서 Anthropic 작업으로 서비스 흐름 연결; 요청한 작업의 상태 변화 | 서버실 문만 열기; 서버 점등을 이익으로 해석 |
| 장기 지출 약속 | Anthropic과 AWS를 잇는 계약이 펼쳐지고 기간/약정이 미래 구간으로 표시됨 | 달력 단독 컷; 약정 전액을 현금으로 즉시 수령 |
| 투자한 회사가 고객이 됨 | 시야를 넓혀 두 관계를 동시에 공개. `투자`와 `서비스 대가/지출 약속`은 다른 색·기호로 구분 | 같은 돈의 확실한 환수나 투자수익 보장 |
| 매출과 이익은 다름 | AWS 운영비 항목이 별도로 보이고 약정·실현 매출·이익이 구별됨 | 전기 설비 사진에 내레이션만 얹기 |
| 두 역할의 결말 | 도입의 동일 무대로 돌아와 투자자와 공급자 역할이 함께 남음 | 관련 없는 유리 건물 외관 엔딩 |

이 관계의 확인용 1차 자료: [Amazon 추가 투자 발표](https://www.aboutamazon.com/news/company-news/amazon-invests-additional-5-billion-anthropic-ai), [Anthropic 컴퓨팅 발표](https://www.anthropic.com/news/anthropic-amazon-compute). 실제 직원·실제 서명 장면이 아닌 설명용 모형이다. 지분 투자, 서비스 계약, 지출 약속과 이익을 합치지 않는다.

## 6. 전체 제작 전과 최종 검수

1. 대본과 관계표를 함께 만들고 서로 다른 연출안 중 이해가 쉬운 안을 고른다.
2. 훅·핵심 관계·결말의 거친 콘티와 가장 어려운 사건의 짧은 애니매틱을 만든다. 인물이 있으면 같은 단계에 인물 행동 시험을 포함한다.
3. 실제 프레임에서 주체, 전달 방향, 관계 변화, 장면 연속성을 확인한다. JSON 필드가 채워졌거나 물체가 움직였다는 사실로 의미 전달을 통과시키지 않는다.
4. 관계 전달이 된 뒤 어셋/모션/조명 순으로 고도화하고 원격 GPU에서 최종 렌더한다. 디스크·사용량 점검은 기존 지침을 따른다.
5. 최종 합성에서 다시 대조한다. 자막이나 크롭이 관계를 숨길 수 있다. QA에 `story_alignment`, `miniature_craft`, `character_action`, `technical`, `listening`을 분리한다. 실제 확인한 구간을 남기고 미검수는 not_performed로 쓴다.

이 기준은 추가 사용자 승인을 받으라는 뜻이 아니라 제작자가 먼저 해결해야 할 품질 기준이다. 스타일 요구가 바뀌어도 이야기-그림 일치는 유지한다.
