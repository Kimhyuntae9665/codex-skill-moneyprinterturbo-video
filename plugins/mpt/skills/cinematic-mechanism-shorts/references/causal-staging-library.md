# 화면이 문장을 설명하게 만드는 연출 도구함

2026-09-06 `archi_trivia1` 12편의 전 구간 프레임 표본과 4개 세부 구간에서 추출했다. [관찰 근거와 한계](archi-trivia-study.md)를 참조한다. 아래 Blender 방법은 **우리 구현 제안**이며 원작자가 사용한 도구를 알아냈다는 뜻이 아니다. 기본 외형은 사용자가 선택한 NVIDIA v2를 발전시킨 정교한 미니어처다.

## 선택 원칙

대본의 핵심 동사를 먼저 고른다: 투자한다, 주문한다, 공급한다, 이용한다, 청구한다, 연결한다, 기다린다. 이어 그 동사가 일어나기 전과 후를 관객이 구분할 수 있는 사건으로 만든다. 돈이 움직이는 장식만으로 투자·대출·매출·이익이 모두 설명되지는 않는다. 행위자, 수신자, 거래 종류가 보여야 한다.

한 편에는 아래에서 어울리는 2~3개만 고른다. 12편을 학습했다고 모든 효과를 한 편에 넣지 않는다. 건축 영상의 터널·폭발·단면을 기업 이야기의 기본 소재로 바꾸지 않는다. 추가 보고서를 매번 만들 필요 없이 기존 `visual-treatment.md`와 `story-visual-map.md`에 선택 이유를 짧게 기록한다.

## 구도는 정보의 크기를 바꾼다

거리만 다른 세 카메라를 준비하지 않는다. 필요한 정보 층을 선택한다.

- **관계 전체:** 두 회사, 고객, 돈/서비스의 방향. 누가 누구에게 무엇을 주는가?
- **사건 접점:** 주문 접수, 계약 전달, 서비스 이용 시작. 정확히 무엇이 바뀌는가?
- **결과 공간:** 고객 증가, 대기 해소, 새로운 의존 관계. 이 사건으로 누가 유리해졌는가?

매 컷마다 기준 위치·로고·인물 복장·물건 중 하나 이상의 알아볼 수 있는 단서를 이어간다. 과도한 얕은 심도로 거래 상대나 화살표 끝을 흐리지 않는다. 단면은 보이지 않던 정보를 드러낼 때만 쓴다. 의도적으로 제거한 벽은 깔끔한 단면·외곽으로 표현하고, 지붕 없는 미완성 건물을 설명 없이 노출하지 않는다.

## 접촉이 있는 동작과 인물

이번 12편 표본만으로 원작의 반복 인물·리그·얼굴 생성법은 알 수 없다. 다음은 사용자 요구에 따른 **우리 미니어처 제작 기준**이다.

인물은 장면마다 같은 목각 모형을 앉혀 두는 장식이 아니다. 고객은 주문하고, 담당자는 접수하며, 작업자는 연결하고 확인한다. 필요 없는 군중은 만들지 않는다. 인물이 있는 핵심 장면에는 `의도 → 손/도구의 접촉 → 대상의 변화 → 인물의 반응` 중 이야기에 필요한 부분을 실제로 연출한다.

전달 동작 예: 사람이 서류를 집기 전에는 책상에 지지 → 집는 순간부터 손과 함께 이동 → 상대가 받거나 책상에 내려놓을 때 소유/지지 전환 → 손은 떨어지고 서류는 남는다. 제약/부모 관계 전환을 쓴다면 위치가 튀지 않는지 먼저 짧게 테스트한다. 손이 물건을 통과하거나 종이가 공중에서 자동 이동하면 다시 만든다. 상반신과 손이 잘 보이는 구도가 불필요한 얼굴 근접보다 유리하다.

완성도는 둥근 프리미티브의 개수가 아니라 옷 실루엣, 관절의 자연스러움, 손/소품 접촉, 의자 높이, 바닥 그림자, 책상·모니터의 비례에서 판정한다. 대표 인물 하나의 전달/작업 동작이 합격한 뒤 재사용한다.

## 문장과 화면의 시간 맞추기

관찰한 자막에서는 “진짜 문제는”, “하지만”, “한 칸 나아갈 때마다” 같은 연결어가 다음 시각 정보를 예고했다. 이를 모든 문장에 기계적으로 붙이지 않는다. 핵심 명사가 나올 때 대상을 식별하고, 동사에서 동작이 시작되며, 결과 절에서 변화한 상태가 보이도록 한다.

한 사건은 `식별 → 동작 → 결과를 볼 시간`을 가진다. 결과가 보이기 전에 다음 컷으로 넘기는 문제를 GPU나 배속으로 해결하지 않는다. 설명이 복잡하면 보조 사실을 덜거나 길이를 늘린다. 표본 길이 72~79초를 모든 편의 강제 길이로 삼지 않는다. 1.30× TTS 기본 설정은 유지하되 실제 음성에 맞춰 검수한다. 이번 연구는 연속 청취나 원작 억양 분석을 완료한 기록이 아니다.

## Amazon 적용 예: GPU 화면으로 덮지 않는 관계 연출

아래는 사실 확인을 마친 거래에 맞춰 사용할 **계획 예시**다. 특정 금액·조건·매출 실현을 주장하거나 이미 렌더했다고 보고하지 않는다.

1. 훅: 회사 A의 투자를 받은 회사 B가 A의 서비스 고객으로 나타난다. 회사 표지와 `투자`, `서비스 고객`의 역할을 구분해 궁금증을 만든다.
2. 접점: 투자 관계를 서류/거래 사건으로 보여준다. 투자금과 구매 약정을 같은 물건으로 뭉개지 않는다.
3. 사용: B가 AWS라고 명시된 서비스 구역에 작업을 맡기고 결과를 받는다. 서버 복도만 보여주지 않고 사용 주체와 공급 주체가 연결된다.
4. 경제적 결과: 확인된 범위에 맞춰 사용료 또는 장기 구매 약정을 표시한다. 약정이면 미래 시간축을 사용하고 현금 수령·이익으로 묘사하지 않는다.
5. 회수: 첫 구도로 돌아와 투자 관계와 서비스 관계를 함께 보여준다. 실제 근거가 없다면 금액이 같은 원을 그리며 돌아오는 연출은 쓰지 않는다.

NVIDIA에도 원리는 동일하다. 연결 전후의 접점과 상대 역할을 확대하고, 마지막에는 처음의 칩이 더 넓은 시스템에서 어떤 역할인지 보이게 한다. 모든 회사의 이야기를 서버·회로로 통일하지 않는다.

## 제작 순서와 합격 기준

콘티의 사건 대응 → 가장 어려운 5~10초 동작 프리비즈 → 미니어처 어셋/접촉 보완 → 재질·조명 → 원격 GPU 본 렌더 순서로 진행한다. 5~10초는 시험 범위의 출발점이며 모든 쇼트의 길이 제한은 아니다. 이번 연구에서 새 Blender 렌더 실증을 한 것은 아니므로 제안 방법은 최초 적용 때 검증한다.

기존 QA에 아래 세 질문을 추가한다: (1) 화면에서 동작을 일으킨 주체와 받는 대상이 보이는가? (2) 다음 구도로 넘어가도 같은 관계로 알아볼 수 있는가? (3) 결말의 상태가 도입 질문에 답하는가? 새 자동 점수나 형식 검사로 통과시키지 말고 실제 프레임·동작을 근거로 판정한다.
