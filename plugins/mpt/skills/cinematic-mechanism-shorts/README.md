| 0–9초 | 일상 사물을 이상하게 다시 소개 | 문에서 승강로 안으로 들어가 로프·상자를 보여줌 |
| 10–17초 | 규모와 개인 경험에 연결 | 여러 승강기 → 분포 → 다시 한 사람의 공간 |
| 18–26초 | 첫 직관의 한계 | 로프를 늘리는 방법을 제시하되 끊어지는 가정을 유지 |
| 27–45초 | 역사·두 번째 해결책·남는 문제 | 과거 리프트와 로프 → 완충 장치 → 낙하 거리 |
| 46–59초 | 핵심 전환과 부품 접근 | 상자에서 측면 레일·쐐기·감시 장치로 시선 이동 |
| 이후 | 작동과 역사적 의미를 닫음 | 제동 과정을 설명하고 익숙한 승강기 모습으로 복귀 |

이 시간표는 그대로 베낄 템플릿이 아니다. ‘시청자의 가설을 하나씩 수정한다’는 기능을 옮긴다. 도입이 반드시 과장된 질문 한 문장이어야 하는 것도 아니다. 이 표본은 평범한 장소 소개로 시작하지만, 거의 즉시 공간을 열어 시각적인 약속을 건다.

### B. 하나의 물체를 따라 시스템을 건넌다

빗물 영상은 정보 카드 여러 장을 쓰지 않고, 하나의 흐름을 따라가며 전체 도시 구조를 설명한다. 회사 이야기에는 데이터 패킷, 전력, 주문, 반도체 웨이퍼, 계약으로 예약된 용량을 이 역할에 사용할 수 있다. 돈을 쓴다면 투자·매출·이익·지분을 같은 흐름으로 합치지 않고 각각의 실제 관계를 유지한다.

### C. 처음의 풍경을 다시 보게 한다

마지막은 ‘좋아요와 구독’보다 앞서 설명의 보상을 준다. 길, 강, 엘리베이터, 건물의 첫 모습으로 돌아가되, 이제 시청자는 보이지 않던 구조를 안다. 회사 이야기의 엔딩도 같은 역할을 할 수 있다. ‘그래서 이 회사는 무엇을 통제하는가’라는 명확한 결론을 화면의 변화로 닫는다.

## 4. 화면: 같은 공간을 다른 깊이에서 보여준다

| 화면 단계 | 기능 | 필요한 실제 변화 |
|---|---|---|
| 환경을 포함한 전경 | 크기와 맥락을 빠르게 이해 | 주변 사람·도로·물·랙과 주인공의 관계 |
| 접근·측면 | 어느 부분을 볼지 지정 | 시야가 중요한 부품으로 좁아짐 |
| 단면·투시·분해 | 보이지 않던 구조 공개 | 벽·외피 제거, 내부 레이어 분리 |
| 동작의 근접 화면 | 원인을 이해 | 끼움, 제동, 흐름, 하중 전달, 용량 채움 |
| 결과 전경 | 앞 동작의 효과 확인 | 수위·안정성·연결·가동 상태가 달라짐 |

원작은 사진 같은 환경만 쓰지 않는다. 회색 미니어처, 흰 배경의 기술 모형, 지하 단면, 도면풍 화면도 섞는다. 다만 이들이 설명 대상과 연결되어 있다. 매번 관계없는 멋진 영상을 갈아 끼우는 방식과 다르다.

‘동적’이라는 기준은 움직이는 픽셀 수가 아니다. 자막이 커지거나 조명이 번쩍여도 물건의 작동 원리가 더 잘 보이지 않으면 핵심 연출 점수는 낮다. 반대로 5초 동안 같은 공간에서 부품 하나가 끼워지는 장면은 충분히 역동적이고 유익할 수 있다.

### 방향과 연결에서 지킬 것

- 같은 장면군에서는 입구·출구, 좌우 관계, 주요 부품 수와 연결을 유지한다.
- 정확한 얼굴이나 배경 창문까지 모두 같게 만들 필요는 없지만, 그 차이가 사실 설명을 바꾸면 고친다.
- 물길, 케이블, 레일 같은 주된 연결은 장면이 바뀌어도 의미가 이어져야 한다.
- 차원이 바뀌는 카메라는 목적을 적는다. ‘멋진 회전’보다 ‘가려진 측면 연결을 보여줌’이 좋은 지시다.
- 단면이 사실적인 사진처럼 보이면 ‘개념도/재구성’ 표기가 필요한지 판단한다.

## 5. 인물과 이미지의 제작 전략

표본에서 인물은 고정 진행자라기보다 작업자, 관중, 역사적 상황의 등장인물 또는 크기 비교 대상이다. 로프를 당기는 손, 기계를 다루는 몸, 높은 곳에서 보는 시점이 설명을 보조한다. 따라서 모든 컷의 얼굴을 완벽히 고정하는 문제부터 해결할 필요는 없다.

우리 제작에서는 다음처럼 한다.

1. 반복 인물이 필요할 때만 독창적인 기준 이미지를 만든다. 정면·사선·작업 손을 비교한다.
2. 얼굴보다 옷, 장갑, 도구, 손잡는 방향, 역할을 먼저 고정한다.
3. 실제 영상 입력에는 여러 인물이 나란히 있는 시트 전체 대신 필요한 한 뷰를 선택한다. 그렇지 않으면 영상이 분할 화면으로 생성될 수 있다.
4. ‘서 있는 사람’보다 ‘밸브를 잠가 흐름이 바뀌는 사람’을 만든다. 인물의 행동이 대상의 상태를 바꾸게 한다.
5. 손가락·도구 접촉·의상 시대착오·얼굴 변화는 장면별로 확인한다.

원작이 특정 LoRA, 캐릭터 전용 모델, 음성 복제 또는 3D 인물 에셋을 사용했다는 직접 증거는 이번 조사에서 확보하지 못했다. 그런 기술을 사용했다고 추측으로 확정하지 않는다.

## 6. 나레이션과 자막

중복 제거한 자동 자막에서 한글 음절 수를 전체 재생시간으로 나눈 값은 표본에서 약 6.32–7.82, 중앙값 약 7.20이었다. 이는 숫자 읽기·영어·무음·ASR 오류를 포함하지 못하는 **내용 밀도 근사치**다. ‘정확히 초당 7.2음절로 말한다’는 측정은 아니다.

옮겨야 할 것은 속도 수치 하나보다 문장 역할이다.

- 익숙한 사물을 가리킨다.
- 예상과 다른 조건을 덧붙인다.
- 쉬운 비유나 작은 동작으로 설명한다.
- 그 동작의 결과를 짧게 확정한다.
- 새 제약이 등장하면 다음 질문으로 넘어간다.

우리의 1.30배 TTS 선호는 시작 설정으로 유지하되, 보이스마다 기본 속도가 다르므로 실제 길이를 확인한다. 억양을 높이려면 모든 문장을 크게 읽히는 대신 질문·반전·결과의 톤을 구분한다. 무음은 먼저 편집하고, 그 편집된 음성에 화면과 자막을 맞춘다. 무조건 0.5초씩 쉬거나 모든 틈을 제거하지 않는다.

원작 자막은 짧은 한국어 구절을 흰색 굵은 글씨와 어두운 윤곽으로 자주 보여준다. 화면의 맨 아래보다 아래쪽 중앙에 놓이는 경우가 많다. 이는 대상의 위치에 맞춰 조절한다. 우리 기준의 시작 실험 범위는 화면 높이 54–68%이며, 정확한 원작 픽셀 측정값이 아니다.

숫자·영문 설명선에는 생성 오류처럼 보이는 텍스트도 관찰됐다. 그 결함까지 복제하지 않는다. 기간·단위·화살표·수치는 편집 단계에서 정확한 텍스트로 합성한다. 화살표 머리가 수치 뒤에 숨지 않도록 등장 중간과 정착 후를 모두 본다.

Typecast의 공식 이름은 **필재**이며 일부 자동 자막에는 필제·필젤로 잘못 나온다. 공식 [캐릭터 소개](https://typecast.ai/kr/learn/typecast-new-editor-characters/)에서 음성 성격을 확인할 수 있다. 이것만으로 원작의 사용 보이스를 인증하는 것은 아니다.

## 8. 바로 적용할 제작 공정

### ① 먼저 가장 어려운 3–8초를 만든다

전체 대본보다 먼저 가장 위험한 장면을 지정한다. 냉각수라면 채널 내부 흐름, 네트워크라면 패킷의 실제 경로, 건축이라면 지지·하중 전달이다. 이 장면이 실패하면 다른 장면을 아무리 많이 만들어도 설명은 무너진다.

### ② 원리와 화면의 기준을 고정한다

대상의 크기·좌우·입출구·재료·환경을 한 장에 적는다. 사실적으로 보이는 것과 실제 구조가 맞는 것을 구분한다. 중요한 치수는 원자료가 있을 때만 사용한다. 원자료가 없으면 개념 모형으로 명시한다.

### ③ 음성의 실제 타임라인을 만든다

한국어 발음이 자연스러운 단위로 합성하고, 앞뒤 불필요한 무음을 줄인다. 원음·편집음·타임코드를 보존한다. 문장 종결과 동작의 결과가 만나는 지점을 먼저 정한다.

### ④ 생성 방식은 장면마다 고른다

- 독립 전경·매크로: 텍스트에서 영상 생성.
- 동일 물체·인물 유지: 승인한 이미지를 기준으로 영상 생성.
- 직전 동작의 연속: 승인된 마지막 프레임에서 이어 생성.
- 정확한 연결·접촉: 검증한 3D 또는 명확히 표시한 기술 모형.

프레임 연결은 무제한으로 이어가지 않는다. 변형이 누적되면 기준 이미지로 되돌아간다. 생성한 장면은 모두 사용할 필요가 없다. 시작·끝의 오류를 버리고 설명이 되는 구간만 선택한다.

### ⑤ 프롬프트는 ‘대상 + 행동 + 카메라 목적’으로 쓴다

다음은 특정 원작 프롬프트의 복사가 아닌, 이번 연구를 바탕으로 만든 독창적인 예시다.

```text
A copper lid lifts and slides clear of a server cold plate, exposing one
connected serpentine passage. The plate stays on the same dark green circuit
board in a believable industrial test bench setting. Keep both hose ports on
the left and keep the divider walls unchanged. Coolant is confined inside
the metal channel; it never pours onto bare chips. The camera makes a slow
oblique approach during the lift, ending where the entire passage is visible.
Realistic machined copper, soft directional light, restrained depth of field,
documentary technical visualization. One continuous vertical 9:16 shot.
No text, measurements, logos, UI, dialogue, extra ports or split screen.
```

‘시네마틱하고 역동적으로’만 쓰지 않는다. 어떤 물체가 어떻게 변하고, 마지막에 무엇이 보여야 하는지를 쓴다. 단일 동작부터 성공시킨 뒤 두 번째 카메라 비트를 추가한다.

### ⑥ 후합성·소리·검수를 별도 단계로 둔다

수치와 화살표를 정확하게 붙이고, 한글 자막이 작동 부품을 가리지 않게 한다. 효과음은 접촉·제동·열림·흐름의 순간에 맞춘다. BGM은 질문 구간의 긴장을 돕되 음성을 덮지 않는다. 원작의 음성·음악을 추출해 재사용하지 않는다.

## 9. 오픈소스와 실제 실행 가능성

아래는 원작자가 사용했다고 밝혀진 목록이 아니라 우리 구현 후보이다. 현재 모델 버전과 라이선스는 도입 시 다시 확인한다.

| 도구 | 우리에게 필요한 역할 | 이번 확인 상태 / 제약 |
|---|---|---|
| [Blender](https://www.blender.org/) | 실제 단면·분해·조립·카메라·흐름의 기하학 검증 | 로컬 5.2.1 LTS 실행 및 독창적 모델 렌더 시험. 복잡한 사실적 씬은 제작·렌더 비용이 큼 |
| [FFmpeg](https://ffmpeg.org/) | 음성 트림, 프레임 추출, 구간 편집, 합성, 인코딩·검증 | 로컬 9.0.1 사용. 파일·프레임 검증은 지각적 품질 보증이 아님 |
| [PySceneDetect](https://github.com/Breakthrough/PySceneDetect) | 외부 레퍼런스의 컷 후보 탐지 | 문서 확인. 이번 측정은 FFmpeg scene 점수로 수행; 이 패키지 실행으로 보고하지 않음 |
| [WhisperX](https://github.com/m-bain/whisperX) | 음성 인식과 단어 수준 정렬 후보 | 문서 확인. 이번 음성에는 사용하지 않음. 언어별 정렬 모델·환경 확인 필요 |
| [ComfyUI](https://github.com/Comfy-Org/ComfyUI) | 생성 모델과 참조 조건을 재사용 가능한 그래프로 자동화 | 공식 저장소 확인. 이것 자체가 영상 모델은 아니며 가중치·GPU·워크플로가 필요 |
| [Wan 2.2](https://github.com/Wan-Video/Wan2.2) | 오픈 가중치 기반 T2V/I2V 후보 | 공식 예제의 TI2V-5B 720p 경로는 24GB VRAM급 GPU를 설명. 현재 Intel Arc 환경에서 해당 경로를 실행 검증하지 않음 |
| [LTX-2](https://github.com/Lightricks/LTX-2) | 참조 프레임·영상 생성·제어 파이프라인 후보 | 현행 공식 문서 확인. 구형 LTX-Video와 버전·모델·라이선스를 섞지 않음. 로컬 추론 미검증 |
| [LTX-Video](https://github.com/Lightricks/LTX-Video) | 경량·증류 모델을 포함한 이전 계열 후보 | 코드 라이선스와 [가중치별 라이선스](https://huggingface.co/Lightricks/LTX-Video) 구분. ‘오픈소스라 무조건 무료 상업 사용’으로 단정하지 않음 |

추가로 제작사 [공개 LTX Video 데모](https://huggingface.co/spaces/Lightricks/ltx-video-distilled)의 **0.9.8 13B Distilled**로 실제 생성 영상 세 개를 받았다. 닫힌 냉각판은 경첩 달린 상자로 변했고, 열린 통로는 필요한 흐름 동작을 입증하지 못했으며, 작업자 컷에서는 밸브가 빠졌다. 따라서 세 파일 모두 ‘생성 성공’과 ‘장면 채택 실패/미충족’을 나눠 기록했다. 이 결과를 현행 LTX-2나 Flow의 품질 평가로 일반화하지 않는다.

현재 컴퓨터에는 Intel Arc 130T가 확인되었고 NVIDIA CUDA 경로는 확인되지 않았다. 따라서 ‘Wan을 설치하면 바로 원작 수준 영상이 나온다’고 말할 수 없다. 우선순위는 **접근 가능한 생성 서비스로 시각 수준을 시험하고, 구조를 정확히 통제해야 하는 곳에 로컬 3D를 쓰는 것**이다.

조사 도중 사용자가 원격 GPU 사용을 요청했고, 해당 컴퓨터에서 **RTX 4060 8GB, RAM 약 32GB, Ryzen 7 3700X**를 확인했다. 전용 폴더에 공식 Blender 5.2.1을 설치하고 체크섬을 확인한 뒤 Cycles/OptiX 렌더링을 실행했다. 1080×1920·12샘플·OptiX 디노이즈 시험의 연속 프레임은 약 0.83초였고, 전체 렌더 초반에는 약 0.65초도 관찰했다. 로컬의 720p·6샘플 CPU 렌더와 설정이 달라 공정한 배속 비교는 아니다. 이 GPU에서 대형 영상 생성 모델까지 실행한 것은 아니다.

원격에 별도 이미지 생성 환경도 만들었다. **SDXL 1.0 base**의 768×1344·25단계 이미지 두 장은 캐시가 있는 상태에서 각각 약 21.26초와 21.30초, 최대 할당 VRAM 약 5.21GiB로 생성했다. 밸브·손 시험은 손 누락과 연결 오류로 작동 설명에 채택하지 않았고, 서버실 전경은 일반 배경 후보로 분류했다. 따라서 GPU는 속도를 해결하지만 모델의 지시 이행과 구조 정확성까지 자동으로 해결하지는 않는다.

서버실 이미지를 활용한 추가 LTX 4초 영상 요청은 서비스 오류로 파일을 받지 못했다. 총 요청은 네 번, 실제 수신 영상은 세 개다. 원인을 제공하지 않은 오류를 임의로 할당량 부족이라고 해석하지 않았다.

Flow의 공식 [생성 도움말](https://support.google.com/flow/answer/16353334?hl=en)은 텍스트·프레임·참조를 활용하는 방법을 설명한다. [크레딧 안내](https://support.google.com/flow/answer/16526234?hl=en)의 2026-09-05 확인값에서는 무료 일일 50크레딧, 무료 크레딧의 Veo 3.1 사용 제한, 모델별 비용이 구분되어 있다. 예컨대 비 Ultra 기준 Lite는 생성당 10, Fast는 20이며 Gemini Omni Flash 8초는 25로 안내된다. 실제 계정·UI에서 다시 확인해야 하고, 무료 크레딧으로 모든 모델을 쓸 수 있다고 가정하면 안 된다.

예산은 완성 분량보다 **재시도 수**로 계산한다. 예를 들어 24개 장면을 평균 두 번씩 만들고 생성당 20크레딧이라면 960크레딧이다. 이는 가상 산식이지 이번 지출이 아니다. 음성·업스케일·음악 비용은 별도다. 강좌의 ‘영상 한 편 천 원’만으로 예산을 잡지 않는다.

## 10. 이번 구현 시험과 실패에서 얻은 규칙

시험 주제는 특정 제품의 설계도가 아닌 **콜드플레이트 방식의 서버 냉각 개념**이다. [NVIDIA 냉각 설명](https://blogs.nvidia.com/blog/liquid-cooling-ai-factories/) 본문에서 냉각판·냉각수·폐회로 설명을 확인했다. [시설 참조 설계](https://docs.nvidia.com/dsx/facilities-infra/reference-design-overview)는 추가 참고 링크이며 본문 전체 열람은 응답 크기 제한으로 완료하지 못했다. 정밀 열유체 시뮬레이션은 하지 않았다.

시도한 것은 다섯 시점의 원본 3D 장면, 뚜껑의 이동, 연결된 통로 속 흐름 표시, 호스와 열교환 장치의 공간 관계, 한국어 TTS, 음성에 맞춘 편집이다. 파란색·주황색 점은 설명용 흐름 표시이며 냉각수 속 실제 고체 입자가 아니다. 외형과 치수는 개념 모형이다.

실제 시험에서 다음 문제를 찾았다.

1. 생성한 구리 냉각판 이미지는 재질이 훌륭했지만, 채널이 독립된 동심원처럼 보여 연속 흐름 설명에 부적합했다. 예쁜 이미지를 곧바로 사실 증거로 쓰지 않는 규칙이 필요하다.
2. Blender 뚜껑은 사선 카메라에서는 열렸지만 다음 상부 카메라의 시야를 막았다. 뚜껑을 시선 밖으로 옮겨 해결했다. 컷별 카메라를 따로 검수해야 한다.
3. 경로 끝에서 시작으로 돌아가는 점을 보간하면 벽을 가로지를 수 있었다. 리셋 구간의 가시성을 없애고 프레임별 위치를 제어했다.
4. 단순한 회색 장비와 깨끗한 재질은 작동 원리 시험에는 유용하지만 원작의 사실적인 환경·인물·다양한 카메라 수준과 차이가 있다. 기하학 구현 통과와 스타일 재현 통과를 분리했다.
5. 통로를 나누는 벽의 끝이 외벽과 미세하게 떨어져 있으면 의도하지 않은 우회로가 생긴다. 분리벽을 외벽과 겹치도록 연장했다. 정해 둔 점의 경로만 맞는 것으로 유체 구조 전체를 검증했다고 해서는 안 된다.
6. 3D 기준 이미지를 넣어 재질을 개선한 두 번째 이미지는 시각적으로 더 사실적이었지만 분리벽과 외벽의 연결을 보존하지 못했다. 미술 방향 예시로 남기고, 정확한 작동을 증명하는 장면으로 채택하지 않았다.

**실행 결과의 최종 파일·분량·검수 상태는 이 문서의 마지막 실행 기록에 명시한다.** 생성 서비스는 계정 접근이 실제로 확보된 경우에만 완료로 보고한다. 로컬 3D 시험만으로 Flow 생성이나 원작과의 동등한 품질을 입증했다고 하지 않는다.

## 11. 회사 이야기로 옮기는 방법

아래는 연출 아이디어이며, 해당 기업에 관한 새로운 사실 주장이나 투자 추천이 아니다. 실제 제작 시 계약과 최신 자료를 별도로 검증한다.

| 이야기 후보 | 첫 물체 | 숨은 구조를 보여줄 동작 | 엔딩의 시각적 답 |
|---|---|---|---|
| 반도체 회사의 네트워크 사업 | 칩 하나 | 카메라가 칩 밖으로 나가 스위치·케이블·다른 랙의 연결을 따라감 | 칩이 아니라 연결된 시스템 전체가 다시 보임 |
| 예약된 공급망 | 웨이퍼 한 장 | 생산·패키징·메모리 단계의 통로에서 예약 조건이 순차 활성화 | 제품 뒤에 필요한 생산 경로가 남음 |
| 네오클라우드 용량 계약 | 꺼진 랙 | 수요 부족 → 계약 조건 충족 → 특정 용량 구매 경로 활성화 | 장비 판매와 용량 부담이 구분된 두 경로 |
| 플랫폼의 사용자 가치 | 한 이용자의 행동 | 여러 서비스가 아니라 하나의 구체적 수익화 경로를 따라감 | 사용자가 많다는 사실과 돈이 생기는 조건의 차이 |
| 맞춤 데이터센터 | 서버 건물 외관 | 외피 제거 → 전력·냉각·칩 배치가 특정 작업에 맞춰 구성 | 표준 건물과 전용 설계의 차이가 실물로 남음 |

반도체 회사의 냉각 영상이라면 제목을 ‘칩을 식히는 물이 뜨거운 이유’처럼 잡을 수 있다. 단, ‘뜨겁다’의 의미와 적용 제품·온도 조건을 검증하고 실제로 찬 물이 필요 없는 모든 시스템이라는 식으로 확대하지 않는다. ‘엔비디아는 ETF다’ 같은 비유 제목은 영상 안에서 구체적으로 어떤 투자·사업 관계를 뜻하는지 풀어야 한다.

## 12. 검수 기준: 파일이 열리는 것과 좋은 영상은 다르다

| 검수 | 확인할 질문 | 통과 근거 |
|---|---|---|
| 사실 | 화면이 대본보다 더 큰 주장을 하지 않는가 | 원자료·주장 원장·개념도 표시 |
| 연결 | 입출구·지지·소유·방향이 일관되는가 | 동작 전후와 전환 프레임 |
| 시야 | 뚜껑·사람·자막이 중요한 동작을 가리지 않는가 | 모든 카메라의 핵심 순간 |
| 움직임 | 실제 변화가 결과를 만드는가 | 연속 재생과 경계 구간 |
| 나레이션 | 발음·쉼·속도가 이해 가능한가 | 실제 청취. 파형만 보면 청취 미실시로 기록 |
| 자막 | 모바일 크기로 읽히고 동작과 맞는가 | 작은 화면 프리뷰, 시작·정착 프레임 |
| 기술 | 전체 파일이 정상 디코딩되는가 | ffprobe·FFmpeg·프레임 수·스트림 검사 |
| 유사도 | 사실적 재질·공간 접근·동작·말투·엔딩이 목표에 가까운가 | 항목별 비교. 기술 통과로 대체 불가 |

구조 검증 스크립트는 누락된 장면 필드, 중복 ID, 타임라인 틈과 겹침, 음성 길이 불일치를 찾는다. 손가락 오류·인과관계·재미·실사감은 판정하지 못한다. 최종 보고에 기술 검증, 프레임 검토, 전체 재생, 청취, 스타일 유사도를 따로 적는다.

## 13. 노출과 조회수를 위한 운영 실험

이 채널의 공개 인기 영상은 ‘평소 보던 것의 숨은 이유’라는 진입점이 강하다. 회사 영상에서도 투자 용어보다 먼저 익숙한 사물과 질문을 보여주는 것이 유망한 가설이다. 다만 특정 편집 기법이 조회수를 만든다고 확정할 자료는 없다.

처음 8편은 두 가지 질문 계열을 비교한다. 예를 들어 ‘당연한 해결책이 왜 안 되는가’ 네 편과 ‘하나의 물체가 어디까지 가는가’ 네 편이다. 한 편 안에 서로 무관한 재미 요소를 쌓기보다, 마지막까지 따라갈 질문을 유지한다. 썸네일은 주인공 물체와 한 문장으로 별도 출력하고, 영상 첫 프레임은 바로 행동을 시작한다.

게시 후 24시간·7일의 결과를 같은 기준으로 기록하되 게시 시점·주제·길이 차이를 함께 본다. YouTube가 설명하는 [Shorts 성과 지표](https://support.google.com/youtube/answer/12220281?hl=en)에서 머물러 시청한 비율, 참여 조회수, 평균 시청시간·평균 시청률을 구분한다. 공개 조회수와 좋아요만으로 이 값을 역산하지 않는다. ‘시청률 몇 %면 무조건 바이럴’ 같은 보편 임계값도 넣지 않는다.

개선 우선순위는 첫 장면에서 대상과 질문이 읽히는지, 첫 반전까지 기다릴 이유가 있는지, 내부 작동이 자막 없이도 보이는지, 엔딩에서 질문이 해결되는지다. 조회수가 낮다고 무조건 TTS를 더 빠르게 만들거나 컷 수부터 늘리지 않는다.

## 14. 스킬 사용법과 완료 조건

호출 예:

```text
$cinematic-mechanism-shorts
AI 서버 냉각의 숨은 원리를 신비한 건축사전처럼 공간을 열어 보여주는
한국어 Shorts로 만들어줘. 사실적인 생성 장면을 목표로 하고,
먼저 가장 어려운 내부 흐름 장면을 짧게 검증해줘.
```

회사 리서치가 필요한 경우:

```text
$wallstreet-edge-shorts
엔비디아 네트워크 사업에서 흥미로운 질문을 찾고,
화면 제작은 cinematic-mechanism-shorts를 적용해줘.
```

결과물은 영상, 썸네일, 대본·출처, 장면 계획, 재사용할 프롬프트 또는 코드, 검수 기록으로 구성한다. 원작의 영상 파일·대본·음성·음악을 새 콘텐츠나 배포 패키지에 복제하지 않는다. 원작의 구성 원리를 가까이 연구하되, 표현과 소재는 새로 만든다.

이번 스킬은 ‘비슷하게 해라’라는 문장만 추가하지 않는다. **실사형 영상 경로 선택, 첫 장면의 실제 대상, 내부 구조 공개, 동작의 인과관계, 생성물 선별 편집, 음성 선행, 문장과 컷 동기화, 시야·연결·유사도 검수**를 실행 기준으로 만든다.

## 2026-09-05 추가 연구: 카메라보다 설명 공간을 바꾼다

기존 표본과 다른 8편, 총 978초(16분 18초)의 메타데이터·자동 전사문과 5초 간격 199장 프레임을 추가 비교했다. 풍력 날개·스카이트리·옹벽·잠수 가두리는 주요 구간을 0.5초 간격으로도 확인했다. 원본별 링크·타임스탬프·적용 예는 [추가 장면 전개 연구](references/followup-direction.md)에 있다. 정상 속도 전체 청취나 원작 제작 도구 확인을 마쳤다는 뜻은 아니다.

가장 큰 차이는 주제 하나를 유지하면서 표현 공간을 바꾸는 것이다. 외관→접점→부품 동작→전체 결과, 또는 지도→운송→조립처럼 시청자의 다음 질문에 맞춰 장면을 설계한다. 우리 콘티에는 질문, 표현 방식, 실제 상태 변화, 다음 장면의 연결 단서를 기록한다. 같은 물체의 앵글 교체를 새로운 사건으로 세지 않는다. 연속 세 장면이 같은 상태라면 검토하되, 동작의 이해를 해칠 만큼 기계적으로 잘게 자르지 않는다.

GPU 실험도 설치 성공과 화면 채택을 분리했다. ControlNet Canny는 순차 CPU offload에서 576×1024 두 이미지를 약 56–60초에 생성했지만 부품·연결·표시점 의미가 바뀌어 설명 컷에 채택하지 않았다. SVD의 첫 저해상도 세로 시험도 형상 변화와 띠가 나타났다. 설정·리비전·시드·시간·실제 판정은 [GPU 품질 실험](references/gpu-quality.md)에 기록한다. 이 결과를 모든 모델·입력의 실패로 일반화하지 않는다.

모델 설치 전에는 기존 전용 환경·HF 캐시·필요한 파일 형식과 용량부터 확인한다. 저장소 전체 다운로드로 중복 가중치를 쌓지 않으며, 실행 코드는 인증정보를 포함하지 않는다. 스킬의 자동 검사는 계약 구조와 실행 조건을 확인할 뿐, 창의성·물리 정확성·시청지속률을 자동 인증하지 않는다.

FramePack의 수정된 저장 경로도 실제 실행했다. 480×832, 37프레임(1.233초)을 약 1,223초에 얻었지만, 내려와야 할 뚜껑 대신 하단 냉각판이 들려 연결 관계가 깨졌다. 생성 성공과 동작 성공을 분리해 불채택했다. 따라서 현재 8GB 장비의 본편 기본 경로는 **직접 제어한 3D + 실제 회사·제품 자산 + 사건에 따라 바뀌는 설명 공간**이다. 새 모델은 배경 또는 새 검증을 통과한 개별 컷에만 채택한다. 자세한 실행값과 원본 입력 차이는 [GPU 판정 기록](references/gpu-quality.md)에 있다.
